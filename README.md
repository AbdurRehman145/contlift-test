# Contlify Journal — Angular + Supabase blog

A server-rendered blog with categories and tags, built with **Angular 22 (SSR)**, stored in **Supabase**, and published to through the **[Contlify](./docs/README.md)** API.

- `/` lists the latest posts, with category filters and search
- `/categories` shows every category with its post count
- `/blog/category/:slug` and `/blog/tag/:slug` list the posts in a category or under a tag
- `/blog/:slug` shows a post with its cover image, author, tags and related posts
- Unknown posts, categories, tags and pages return a real `404` from the server

## How it fits together

```
Publisher (Contlify, curl, n8n…)            Browser
        │ POST /api/contlify/v1/posts           │ GET /blog/...
        │ X-Contlify-Key: …                     ▼
        ▼                              Angular SSR (src/server.ts, Express)
  server.contlify.ts ─────────────────► public read routes  GET /api/contlify/v1/posts, /categories, /tags…
        │ contlify.config.ts                    │ (used by the route resolvers, server and client)
        ▼                                       ▼
            Supabase (contlify_* tables, secret key, server only)
```

- **`contlify.config.ts`** sets up Contlify with the Supabase storage driver. It also loads `.env`.
- **`server.contlify.ts`** is generated by Contlify. It mounts two sets of routes on the Express server:
  - the public read routes that the pages use;
  - the publishing API, which requires the API key.
- **The Angular pages** load data through route resolvers (`src/app/core/resolvers.ts`) that call the read routes.
  - During SSR the responses are embedded in the page, so the browser doesn't fetch them again.
  - The Supabase secret key never reaches the browser.

## Setup

**Requirements:** Node.js `^22.22` or `^24.15`, which are the versions Angular 22 supports. Odd-numbered Node versions such as 23 run, but print a warning.

1. Install dependencies:

   ```bash
   npm install
   ```

2. Copy `.env.example` to `.env` and fill in the values:

   | Variable | Where to find it |
   | --- | --- |
   | `SUPABASE_URL` | Supabase → Project Settings → API |
   | `SUPABASE_SECRET_KEY` | Supabase → Project Settings → API Keys (secret key). Server-only. |
   | `CONTLIFY_API_KEY` | Any long random string. Publishers send it as `X-Contlify-Key`. |

3. Create the tables. Skip this if your project already has the `contlify_*` tables.
   - Open Supabase → SQL Editor → New query.
   - Paste [`supabase/schema.sql`](./supabase/schema.sql) and run it.
   - The schema also enables Row Level Security with no policies, so the public (publishable) key can't read or write these tables.

4. Run the dev server and open http://localhost:4200:

   ```bash
   npm start
   ```

## Publishing a post

Send posts to the running site, using port 4200 in dev or 4000 in production:

```bash
curl -X POST http://localhost:4200/api/contlify/v1/posts \
  -H "X-Contlify-Key: $CONTLIFY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Hello from Angular",
    "content": "<h2>It works</h2><p>Published through Contlify.</p>",
    "status": "published",
    "excerpt": "A short summary shown on the cards.",
    "coverImage": "https://images.unsplash.com/photo-1498050108023-c5249f4df085?w=1200",
    "author": "Jane Doe",
    "categories": ["Engineering"],
    "tags": ["Angular", "Supabase"]
  }'
```

- Categories and tags are created automatically the first time they're used.
- `content` can be HTML or Markdown.
- To check the connection, call `GET /api/contlify/v1/validate` with the same header.
- See [`docs/api-reference.md`](./docs/api-reference.md) for every endpoint.

## Deploying

The site needs a running Node server: the pages are rendered there, and the Contlify API that talks to Supabase lives there too. A static-only deployment can't reach Supabase.

### Vercel

Vercel doesn't run Angular SSR on its own, so the repo includes two files that set it up:

- [`api/index.mjs`](./api/index.mjs) runs the Angular server (`src/server.ts`) as a Vercel function.
- [`vercel.json`](./vercel.json) controls the build and routing:
  - it builds with `npm run build`;
  - it serves `dist/contlify-blog/browser` as static files;
  - it sends every other request to that function.

`vercel.json` overrides the project's Framework Preset, so leave the dashboard settings alone.

1. In Vercel → **Settings → Environment Variables**, add `SUPABASE_URL`, `SUPABASE_SECRET_KEY` and `CONTLIFY_API_KEY`.
   - Add them for Production, and for Preview if you use preview deployments.
   - `.env` is gitignored, so it's never deployed.
2. Redeploy. Vercel only applies environment variable changes to new deployments.
3. Check the connection:

   ```bash
   curl https://your-app.vercel.app/api/contlify/v1/validate -H "X-Contlify-Key: $CONTLIFY_API_KEY"
   ```

   - `"adapterConnected": true` means Supabase is connected.
   - If the Supabase variables are missing, the function logs show `[contlify] SUPABASE_URL and SUPABASE_SECRET_KEY are not set`.

Allowed hosts are handled automatically:

- `src/server.ts` allows the domains Vercel assigns to each deployment (`VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_BRANCH_URL`, `VERCEL_URL`).
- For a custom domain, also set `NG_ALLOWED_HOSTS=blog.example.com`.

### Other Node hosts

The build output is a regular Node server: `node dist/contlify-blog/server/server.mjs`.

1. Set `SUPABASE_URL`, `SUPABASE_SECRET_KEY` and `CONTLIFY_API_KEY` in the host's environment.
2. Allow your domain. Angular's SSR server rejects requests for hosts it doesn't know about, which protects against SSRF.
   - Either add the domain to `security.allowedHosts` in `angular.json` (it currently allows only `localhost`);
   - or set `NG_ALLOWED_HOSTS=blog.example.com` at runtime.

On any host, point your Contlify destination at `https://your-domain/api/contlify/v1/posts`.

## Project structure

```
contlify.config.ts          Contlify config: Supabase driver, API key, post URL pattern
server.contlify.ts          Express routes: public reads + publishing API (generated by Contlify)
supabase/schema.sql         Tables, indexes and RLS for a fresh Supabase project
api/index.mjs, vercel.json  Vercel deployment: runs the SSR server as a function
src/server.ts               Angular SSR Express server (mounts Contlify, allowed hosts)
src/app/server/             Server-only code: reads Contlify in-process during SSR
src/styles.css              Design tokens (light/dark) and all component styles
src/app/
  app.routes.ts             Routes and the resolver for each page
  app.routes.server.ts      Every route is rendered on request (posts change at publish time)
  core/
    site.ts                 Site name, tagline and description: edit these first
    blog-api.ts             HttpClient wrapper for the read routes
    resolvers.ts            Page data loading, including not-found detection
    page-meta.ts            Title, description, Open Graph tags and 404/503 status during SSR
    post-utils.ts           Excerpts, reading time, cover images, sorting
  shared/                   Post card, category pills, Markdown/HTML content pipe
  pages/                    home, post, category, categories, tag, not-found
```

## Notes

- **Post bodies.** Contlify labels content as Markdown by default, even when it's HTML.
  - `PostContentPipe` passes HTML through and renders real Markdown with [`marked`](https://marked.js.org).
  - Angular's sanitizer then strips scripts and unsafe attributes.
- **Content types.** Types such as `Post` and `Category` come from the `contlify` package. Only type imports are used, so nothing from the package is shipped to the browser.
